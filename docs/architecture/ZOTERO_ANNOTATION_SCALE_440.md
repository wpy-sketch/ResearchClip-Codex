# v4.4.0：当前PDF的30,000条Zotero标准批注

状态：开发验收中，未发布。用户于2026-10-27明确停止IDE开发，目标版本改为v4.4.0。本轮合并尚未发布的Connector和布局改进；原IDE研究材料仅留在忽略的本地artifacts，不作为功能或发布附件。后续ROADMAP阶段不自动实施。

## 复用和边界

沿用Tauri2 + React19 + Rust模块化单体、ZoteroAnnotationRepository/CoordinateAdapter/ReadCache、既有PdfViewerSession、来源绑定与同步队列，不增加全局资源ID、第二正文服务或IDE框架。用户确认范围为**当前PDF已确认来源的全部批注，最多30,000条**，不新增跨文献全库扫描。原始Zotero key仍与实例、library type/ID、父文献和附件共同限定。

依据[官方Web API v3读取与Local API说明](https://www.zotero.org/support/dev/web_api/v3/basics)核对分页、库版本与实例头。目标宿主仍为本机已检查的Zotero10.0.6；本轮真实UI交互受阻，SDK源码、隔离HTTP夹具和Mock不能证明真实XPI兼容。插件规范和认证协议延续[Step17](ZOTERO_CONNECTOR_STEP17.md)。

## 读取和完整性

ZoteroClient保持20条分页及单响应2MiB预算，仅批注整批读取获得300秒总时限；其他来源查询保持12秒。单请求不超过2秒，不代理、不跟随重定向，不写Zotero数据库。每批检查实例、库、父附件、批注键和Last-Modified-Version，分页库版本变化或身份不符则拒绝混合快照。相同版本不同内容拒绝；更高重复版本可合并。

最多读取1500个20条批次，达到边界再以limit=1/start=30000探测，区分恰好完整和超限。累计响应128MiB，序列化快照64MiB，全库只读缓存256MiB；失败不静默截字或删除旧缓存。truncated为true时同步不得推断缺席对象已删除。预算是安全上限，并非保证任意长度的30,000条记录都能在预算内装入。

## 存储与迁移

新增021_zotero_annotation_capacity.sql，将ResearchClip的zotero_annotation_cache重建为字节数不超过64MiB的相同列/主键/外键表。INSERT SELECT原样保留snapshot_json和身份，不重排旧内容。已发布001–020迁移不改。迁移器沿用升级前quick_check、一致快照、快照验证、IMMEDIATE事务、失败回滚和未来版本拒写。仅隔离测试库执行开发验收，不启动默认资料目录验证迁移。

读取快照和同步比较在同一个IMMEDIATE事务发布，内部保存使用嵌套savepoint；任一步失败回滚两者。比较按annotation key建立BTreeMap，批量预算一次计算，变更集中提交；不再逐条扫描全表和逐条提交。未修改记录不增加revision；已变更记录归档旧状态，CAS校验和本地待处理修改保留。同步队列及处理修订各256MiB预算，单条仍1MiB，每来源同步身份记录上限100,000条（含历史删除/待提交身份，与当前PDF读取30,000条分开），避免满额阅读阻止保存新草稿；达到预算时拒绝继续，不能自动清空历史。

## 展示与布局

默认阅读区采用Zotero风格的颜色边线卡片，展示类型、页码、原键、选文、评论和不支持原因。所有数据参与Unicode搜索/颜色筛选及页码、类型、修改时间排序；每页25/50/100条，支持直接页码跳转。分页只减少挂载DOM，不减少缓存或搜索范围。编辑列表、同步记录复用分页组件，编辑与同步按需展开，避免隐藏区域创建30,000组控件。

页面不超过2000个区域时保留现有SVG/DOM定位渲染，密集页面改用有界Canvas（最多约400万像素、DPR上限2），按80条/帧增量绘制全部支持区域。ResizeObserver重绘，卸载取消animation frame并释放观察器；仍使用原始PDF坐标和既有旋转适配，不改PDF或把Zotero ink变成ResearchClip私有笔迹。

布局复用FlexLayout、EditorSession与WorkspacePersistence，提供左右、上下、标签预设、20%–80%比例和原有拖动/隐藏/保存；未打开Markdown时不创建空白面板。图标沿用本轮原创蓝绿黄红文献/回形针设计，不复制Google商标资源。当前运行时依赖版本不新增、不整体升级。
